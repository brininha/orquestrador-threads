# Fluxo de desenvolvimento

*   **Branching:** Utilizaremos um fluxo simples baseado no `main`. Cada tarefa deve ser desenvolvida em uma branch separada, nomeada como `feat/T3.2-mutex` ou `fix/T1.1-out-of-bounds`.
*   **Commits:** Mensagens curtas, em português, descrevendo "o que" e "por que". Ex: "feat: implementa leitura do bd.txt para array estático".
*   **Integração:** Não altere as assinaturas de funções (contratos) na sua branch sem avisar o grupo. Se uma interface definida em `integration-contracts.md` precisar mudar, registre a justificativa no grupo antes de enviar o *Pull Request*.
